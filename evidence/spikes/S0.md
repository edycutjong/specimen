# Spike S0 — pin the agent engine for headless runs

**Verdict: PASS** (2026-11-24 23:38–23:41 WIB, kiro-cli 3.5.0, macOS)

Question: `kiro-cli chat --help` says that when nothing selects an engine, `--no-interactive` runs **v2**. This machine has
`chat.agentEngine = "v3"` set globally. Does passing `--agent-engine v3` explicitly give every headless run the v3 engine
(where standalone `.kiro/hooks/*.json` capture hooks fire), whatever the setting says?

Harness: `spikes/kiro/setup-ws.sh <ws>` builds a scratch workspace (outside this repo) with the toy stdio server
(`spikes/kiro/toy-stdio.ts`) registered in `.kiro/settings/mcp.json` and capture hooks in `.kiro/hooks/capture.json`.

| Run | Command (cwd = scratch workspace) | Exit | Deciding lines |
|---|---|---|---|
| v3 pinned (prompt `prompts/turn-06.md`) | `kiro-cli chat --no-interactive --agent-engine v3 --trust-workspace --trust-tools=@hollowinn "…"` | 0 | `[tool] @hollowinn/search_rooms` · jars written: `pre-hollowinn.jsonl`, `post-hollowinn.jsonl`, `post-mcp.jsonl` |
| v3 pinned, 3 calls (`prompts/turn-04.md`, the S3 run) | same, `--trust-tools=@hollowinn,@hollow-inn-x` | 0 | 2 pre + 2 post jar lines for `hollowinn`, 1 for `hollow-inn-x`, 3 for `@mcp` |
| control: `--agent-engine v2` (`prompts/turn-05.md`), run twice | same prompt, `--agent-engine v2`, `--trust-tools=@hollowinn` then `@hollowinn,@hollow-inn-x` | 0, 0 | `[tool] Running: @hollow-inn-x/search_rooms` · `[denied] tool permission approval is not supported in non-interactive mode. Use --trust-all-tools to auto-approve.` · no jar written |

What this shows:
- The flag wins over the global setting: with `chat.agentEngine = "v3"` set, `--agent-engine v2` produced v2 behaviour (a
  different denial message, `@server` trust entries not honoured, the request routed to the wrong one of two servers that
  expose the same tool names, no hook output). With `--agent-engine v3` every capture run wrote jars.
- Not tested: a profile with the setting *unset*. Changing the shared global setting while sibling projects run headless
  Kiro sessions on this machine would have changed their engine mid-run. The `--help` text plus the v2 control (the flag
  overrides a v3 setting) is the evidence that the flag alone selects v3.

Consequence for the build: every headless call in this repo passes `--agent-engine v3` explicitly (`scripts/record-sessions.sh`,
`specimen file`), `specimen init` checks the engine and says how to set it, and provenance records the engine.
Side finding: never register the same server twice in one workspace — v2 routed a `hollowinn` request to the `hollow-inn-x` copy.

Credits (measured per session from Kiro's own `usage_summary`, `scripts/kiro-credits.mjs`): v3 pin run 0.2114; the v2 control
runs are stored by the v2 engine outside the v3 session store and were not measured (both were denied before any tool ran).
