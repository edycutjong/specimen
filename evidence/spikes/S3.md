# Spike S3 — the `@hollowinn` selector and Kiro's tool-name sanitiser

**Verdict: PASS** (2026-11-24 23:38 WIB, kiro-cli 3.5.0, engine v3 pinned)

Question: does a per-server PostToolUse/PreToolUse matcher `@hollowinn` fire only for that server, and what `tool_name`
does Kiro report for a server key with separators (`hollow-inn-x`)?

Setup (`spikes/kiro/setup-ws.sh`): the same toy stdio server registered twice, as `hollowinn` and as `hollow-inn-x`;
four hooks — `PreToolUse @hollowinn`, `PostToolUse @hollowinn`, `PostToolUse @hollow-inn-x`, `PostToolUse @mcp` — each
appending its STDIN payload to its own file.
Command (prompt `prompts/turn-04.md`): `kiro-cli chat --no-interactive --agent-engine v3 --trust-workspace --trust-tools=@hollowinn,@hollow-inn-x "…"` — **exit 0**.
The agent made 3 calls: `search_rooms` and `quote` on `hollowinn`, `search_rooms` on `hollow-inn-x`.

| Hook | Lines | `tool_name` values reported |
|---|---|---|
| `PreToolUse @hollowinn` | 2 | `mcp_hollowinn_search_rooms`, `mcp_hollowinn_quote` |
| `PostToolUse @hollowinn` | 2 | `mcp_hollowinn_search_rooms`, `mcp_hollowinn_quote` |
| `PostToolUse @hollow-inn-x` | 1 | `mcp_hollow_inn_x_search_rooms` |
| `PostToolUse @mcp` | 3 | all three |

Payload keys (measured): PreToolUse `session_id, hook_event_name, cwd, tool_name, tool_input`; PostToolUse adds
`tool_response`, a **string** holding the server's response text verbatim, e.g.
`"{\"room_id\":\"R-101\",\"nights\":2,\"total\":425,\"currency\":\"USD\"}"`. No timestamp, call id or duration.

What this shows:
- `@hollowinn` fires for exactly that server's calls (not for the `hollow-inn-x` call).
- The sanitiser turns `-` into `_`: `hollow-inn-x` + `search_rooms` → `mcp_hollow_inn_x_search_rooms`. The server/tool
  boundary is then ambiguous, so parsing names is unsafe. Hence the design: the per-server selector, and the hook command
  carries `--server <key>`; no name parsing. The demo server key stays `hollowinn` (no separators).

Fallback (not needed): the `@mcp` matcher with the server filter inside `specimen hook`.
