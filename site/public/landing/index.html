C3 · How it works

Five parts, stitched into one loop.

Capture, inside the agent

Kiro's PreToolUse and PostToolUse hooks run specimen hook on every call to the MCP server and seal it as a jar: request, response text byte for byte, redacted on write. No proxy. The specimen CLI takes p50 465 ms before a call and 474 ms after (Kiro's own hook launch not included).

"trigger": "PostToolUse",
"matcher": "@hollowinn",
"command": "npx --no-install specimen hook post --server hollowinn"

Replay

A fresh server per recorded session; each answer compared with its jar: preserved, rattled, cracked.

MCP TS SDKsame code in the browser

Verdict

SHIP only when the replay is clean on the recorded set, printed with its coverage. Anything else is HOLD.

Questions a judge would ask.

Is the replay on this page real, or a recording?
Real. Your browser runs the cabinet's own replay code (apps/cabinet/src/browser-replay.ts) against the hollow-inn v1, v2 and v2.1 modules over an in-memory MCP transport, and the plate says LIVE with the time it took. If that code cannot load, the shelf shows the committed CLI replay and says RECORDED.
Are the v2 breaks real?
Real changes, made by us on purpose (servers/hollow-inn/CHANGES.md): total became total_cents, the search_rooms default limit fell from 20 to 5, cancel_booking was renamed. Our one run against a server we did not write (server-memory 1.0.0 → 2.2.1) found no break.
Did Kiro really write the fix?
Kiro's curator filed the three bugfix specs; Kiro's Bug Fix workflow wrote each design and task list and executed them into servers/hollow-inn/src/v2_1.ts, headless on the Kiro CLI with no IDE approval step. For two of the fixes the final acceptance ran outside Kiro: turn 43 stopped at its last task and turn 45 hit our timeout (prompts/README.md).
Why not just diff the schema?
An input-schema diff of tools/list saw 2 changes for v2: cancel_booking removed, booking_cancel added. It compares tools and their input schemas, not descriptions or responses, so the quote and search_rooms changes, which show only there, pass it.
Is this the first record/replay tool for MCP?
No. mcp-recorder, AgentVCR and mcpsnoop exist. What differs here is capture inside the agent through Kiro hooks (no proxy) and the closed loop into a Kiro bugfix spec.
