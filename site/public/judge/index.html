Why Frankenstein

Four parts built for different jobs, stitched into one loop.

  1. MCPthe thing under testour demo server hollow-inn, v1 → v2 (3 breaks) → v2.1
  3. HOOKSthe captureKiro PreToolUse / PostToolUse inside the agent, no proxy
  5. REPLAYthe verdict@specimen/core: preserved, rattled or cracked, then SHIP or HOLD
  7. SPECwhere a break becomes worka Kiro Bug Fix spec, the jar as its repro

What holds them together is the jar: a Kiro hook event becomes replay evidence, the replay becomes a verdict and a checked bugfix spec, and the same replay decides whether the Stop hook sends the agent back. Why it needs Kiro: a hook runs inside the agent and sees each call's tool_input and tool_response with Kiro's session_id, so there is no proxy in front of the server (evidence/spikes/S3.md).

Honest limits

Labelled on the jar, not in the small print.

  • Our server, our breaks.

    hollow-inn and its three v2 breaks are ours; the 10 jars come from two Kiro sessions we prompted. SHIP means replay clean on the recorded set (10 jars, 5 of 6 tools: the agent never called get_room), nothing more.

  • Outside the fixture, a null result.

    The one run against a server we did not write found no break. Its 2 unsealed calls also return structuredContent, which a text-only jar cannot compare: a limit of our jar format.

  • Kiro CLI only, headless.

    The Kiro IDE, Spec Correctness and the IDE's bugfix approval steps were not used. Two of the three Bug Fix executions stopped before their final acceptance task, which we ran.

  • The Stop gate is observed, not rated.

    One retained live run per variant. The uncoached break arm ended with no accepted spec: check-spec rejected the curator's draft and the agent stopped to ask.

  • Not the first MCP record/replay tool.

    mcp-recorder, AgentVCR and mcpsnoop exist. What differs is capture inside the agent through Kiro hooks, and the loop into a Kiro bugfix spec.

  • No outside user yet; axe not at zero.

    axe-core still reports color-contrast on the cabinet's jar toe-tags; we do not claim 0 axe violations.
