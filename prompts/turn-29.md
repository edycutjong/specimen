Start a new Feature spec, Requirements-First, named cabinet-ui. Write only .kiro/specs/cabinet-ui/requirements.md (EARS acceptance criteria, numbered requirements). Do not write design.md or tasks.md yet and do not change any other file.

The feature: apps/cabinet, the browser cabinet — the one page a judge opens (https://specimen.edycu.dev/). It runs the REAL replay engine from packages/core in the browser against the REAL hollow-inn server modules (servers/hollow-inn createServer("v1" | "v2" | "v2.1")) over the MCP SDK InMemoryTransport, using the committed jars (jars/racks.json → RACK A and RACK B files, imported as raw text at build time), .specimen/replay.json, .specimen/volatile.json and .specimen/redact.json — exactly the wiring proven by spikes/s1-browser/src/s1-real.ts (read it; it reproduces the CLI result in a production Vite bundle). Nothing on the page is a mock: every state, count, path and value comes from that replay or from a committed file. Stack per .kiro/steering/tech.md: Vite + React 19, TypeScript, static build, SVG jars, CSS animation, fonts self-hosted from @fontsource packages (Grenze Gotisch 900, Atkinson Hyperlegible Next 400/700, Azeret Mono 500/700) — the built page requests no third-party host at all (no CDN, no Google Fonts, no analytics).

The world (design direction "night-lab-specimen"): Frankenstein's specimen lab at night. Riveted iron shelves bolted to a green-black stone wall; glowing jars of preserving fluid with an iron lid and two neck bolts; inside each jar floats the jarred answer drawn as a pale curled "{"; a manila toe-tag on a string at the jar's neck carries the accession number and the tool name; one arched window with three iron bars and a storm behind it — lightning in that window is the replay firing; the lab notebook (ruled paper, a red margin line, cracked at one corner) is where diffs are written. The haunting comes from this mechanism, never from clip-art: no pumpkins, bats, ghosts, cobwebs, no purple.

Tokens (use exactly; one CSS file of custom properties):
--bg #10150F · --glass #192219 · --ink #ECE6D3 · --tag #D9C49A · --label-ink #1E1912 · --muted #8E978A · --before #A8E35F (state preserved) · --after #FF4A2E (state rattled) · --cracked #7A3B31 (state cracked) · --rule #333D31 · --storm #C9D6F2 (window and lightning only, never a state).
Faces: --font-display Grenze Gotisch (Black 900, caps) only for the wordmark, the verdict plate, flag words (ABNORMAL, CRACKED), shelf titles and stamps — never sentences, never identifiers; --font-body Atkinson Hyperlegible Next for every sentence; --font-data Azeret Mono ONLY for tool names (as written, e.g. search_rooms, never re-cased), accession numbers, JSON inputs, diff paths and values, timings, CLI commands. Sizes: verdict 56 px, shelf titles 28 px, toe-tag tool name 16 px data bold, body 18 px, data 15 px; nothing below 14 px anywhere (projector rule). Contrast pairs allowed for text: ink on bg, label-ink on tag, label-ink on after (the flag strip), after on bg only at ≥ 18 px; after on tag is never used. State is never colour alone: a rattled jar also carries the printed ABNORMAL strip, a cracked jar a torn label and the word CRACKED.

What it must cover (requirements, one per area):
1. Cold open: on load the cabinet auto-replays v2 (no click). A lightning flash crosses the barred window, the jars are revealed left to right, row by row; each preserved jar settles green; each rattled jar rattles (translateX ±3px + rotate ±2.5deg, 3 cycles, 540 ms, ease-out), its specimen twitches, its fluid floods from --before to --after bottom-up (700 ms mask), and a red ABNORMAL strip inks across its toe-tag in steps(4) over 320 ms; a cracked jar shows a crack line, dimmed low fluid and a torn CRACKED label. The replay itself runs at full speed; the reveal is paced for the eye (one jar every ~250 ms) and the header states the measured truth, e.g. "10 jars replayed in 41 ms · in this browser · hollow-inn v2 in memory". After the first rattled jar finishes, one rubber stamp "IT'S MOVING" (display face, --after, rotated, decorative, aria-hidden) slams down beside it once per page load. Calm jars only drift (one slow bubble every ~6 s). prefers-reduced-motion: reduce → no shake, no bubbles, no flash (a static window glow), fluid and strip switch instantly, the stamp appears without motion.
2. ServerSwitch: segmented v1 / v2 / v2.1 (a select below 600 px). Switching version dims every jar to "not replayed" until the next replay and shows that version's line from servers/hollow-inn/CHANGES.md under the switch; ReplayButton "Replay cabinet" replays the selected version (disabled while running, shows elapsed ms). v1 is the control (every jar preserved, SHIP v1); v2.1 is the version Kiro fixed from the filed quote bugfix spec.
3. VerdictPlate: the verdict word and version in the display face (HOLD v2 in --after, SHIP in --before), the counts "N preserved · N rattled · N cracked", the coverage line "N jars compared · T of K tools · not recorded: …", and the counter "R red · F filed as Kiro bugfix specs" ("all red jars filed" when F = R) — all computed by packages/core verdict(), never by the UI. Filed ids come from the committed .kiro/specs/*/bugfix.md files (imported raw at build time) using the same rule the CLI uses in packages/cli/src/replay/spec-files.ts; move any pure part the browser needs into packages/core without changing CLI behaviour or its tests. Also "K skipped", "Q quarantined", "S spoiled" when non-zero.
4. CountsPair, the devastating line: "schema diff: N of K tools changed" (N = distinct baseline tools removed or with a changed inputSchema in the v1 → selected tools/list, K = tools in the v1 tools/list; added tools listed after it) beside "replay: T tools · M jars changed" (T distinct tools among rattled + cracked jars, M rattled + cracked jars). Both computed live from the same replay result's schema_diff and jar states.
5. Shelves: one ShelfRow per recorded Kiro session (RACK A, RACK B): rack code in the display face, the task the agent was given (the prompt text from prompts/rack-a.md / rack-b.md, minus the header comment), session id (shortened), call count; jars in seq order on an iron shelf with stencilled position codes on the shelf lip (A1 … A5, B1 … B5). Jars per shelf by width: ≥ 1280 px 8 (6 when the drawer is open), 1024–1279 5, 600–1023 4, < 600 3 (rows wrap). No horizontal scroll at 375 px and 320 px.
6. Jar (SVG, the signature element): glass body, iron lid with two neck bolts, glowing fluid level, the floating curled "{" specimen, manila toe-tag on a string, askew 0.5–1.5° seeded by accession so it is stable; states not replayed · preserved · rattled · cracked · unsealed · skipped. On the tag: accession (data, ≥ 14 px), tool name (data bold, ≥ 16 px), and after a replay one flag word on a red strip (ABNORMAL or CRACKED, display face, label-ink on after). Each jar is a keyboard-focusable button with an accessible name like "SPC-0002 quote — rattled, /total removed, /total_cents added, suspected rename from /total ×100"; a focus/hover tooltip names the broken field. A decorative barcode is aria-hidden. Design input: the jar drawing at ../assets/_jar.js (outside this repo) — copy what you use into apps/cabinet/src and adapt it to React; never link to a path outside the repo.
7. JarDrawer (opens on jar click; right panel 480 px ≥ 1280, 420 px 1024–1279, bottom sheet 70 vh 600–1023, full-screen sheet < 600): header with a mini jar in its state, accession, tool, rack + shelf position, flag; Input (the jarred JSON input, data face); LabReportTable on ruled lab-notebook paper with a red margin line: columns Path · Replayed · Flag · Reference (jarred), flags REMOVED / ADDED / TYPE / VALUE / LENGTH, abnormal rows struck through and flagged in red ink, the "suspected rename ×100" annotation row; the RAW jarred literal is shown as recorded (425.00, never 425); ignored volatile paths; tabs Jarred / Replayed raw bodies; Bugfix spec section. Escape closes; focus returns to the jar; focus is trapped while open.
8. SpecViewer (inside the drawer): renders the committed .kiro/specs/<slug>/bugfix.md that lists the jar (a small local markdown renderer, no third-party library needed for headings, lists, code fences), a provenance line (filed by the specimen-curator agent via `specimen file`, date and Kiro version taken from evidence/slice/01-specimen-file.md), a "check-spec PASS" badge only if core checkSpec() passes for that jar in the browser, and a link to the file on GitHub (https://github.com/edycutjong/specimen/blob/main/<path>). When no spec lists the jar it says "not filed" honestly.
9. GuideStrip, the 60-second judge path: ① Open a red jar → ② Read the bugfix spec filed for it → ③ Switch to v2.1 and replay. Each step ticks when done; step ① pulses once after the v2 auto-replay ends.
10. CabinetFrame + Legend + footer: the night-lab wall (riveted iron frame, the arched barred window with the lightning flash, the stamp "KIROWEEN 2026 · FRANKENSTEIN", the four organs MCP · HOOKS · REPLAY · SPEC joined by surgical cross-stitch sutures and bolts); Legend of jar states drawn small with their words (PRESERVED · RATTLED · CRACKED · UNSEALED · NOT REPLAYED; SKIPPED only if any jar was skipped); SpoiledTray listing quarantined/spoiled lines with file:line and reason (only when non-empty); footer HowJarsWereMade: the hook JSON files from .kiro/hooks (specimen-jar-pre, specimen-jar-post), a link to /.kiro on GitHub, and the line "This page is an interactive demo over the hollow-inn server with jars captured by Kiro hooks. On your own server: capture with the hooks → specimen replay --server <your test instance>".
11. Failure states: if the in-browser replay throws, the cabinet shows the error in the header plate (never a fake result) and offers Retry.
12. Tests (vitest; jsdom where a DOM is needed): the cabinet's replay module run against v1 / v2 / v2.1 in Node reproduces the committed CLI results in evidence/replay/racks-vs-v1.txt, racks-vs-v2.txt and racks-vs-v2.1.txt (verdict, per-jar state, counts, filed ids); the CountsPair numbers for v2; the view-model mapping from a replay result to jar props and accessible names; the drawer's lab report rows for SPC-0002 (the raw 425.00 literal); reduced-motion class switching; a build test that greps the dist output for any http(s) host other than github.com links and fails if one is found. npm test and npm run typecheck at the repo root stay green.
13. Deploy shape: `npm run build -w apps/cabinet` emits a static dist/ at the site root `/` (relative asset paths fine) that Vercel serves as-is; a vercel.json at the repo root with the build command and output directory. Works on Vercel Hobby (no serverless function, no Pro-only feature).
