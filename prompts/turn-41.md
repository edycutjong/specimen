Usage: `specimen init [--root <dir>] [--server-key <key>] [--mcp-command "<cmd>"] [--test-server "<cmd>"] [--allow <tool>]... [--watch <glob>]... [--commit-jars] [--force] [--yes]`. Exit codes: 0 done · 2 usage error or a missing answer in a non-interactive run.

What it does, in this order, printing one line per file it writes or leaves alone (`wrote <path>` / `kept <path> (exists; use --force)`):
1. Root = `--root` or the workspace root. Server key = `--server-key`, else, when STDIN is a TTY, ask with the keys found in `<root>/.kiro/settings/mcp.json` (`mcpServers`) listed; with no TTY and no `--server-key`: print "specimen init: --server-key is required without a terminal" to stderr, exit 2. The key must match /^[A-Za-z0-9]+$/ (no separators — the hook selector `@<key>` and the sanitised tool names depend on it; say so in the error, exit 2 otherwise).
2. mcp.json: if `<root>/.kiro/settings/mcp.json` has no entry for the key, `--mcp-command "<cmd>"` adds `{ "command": <first word>, "args": [<rest>] }` under `mcpServers.<key>` (keep every other entry and key untouched, 2-space JSON); with neither the entry nor `--mcp-command`: print "no mcp.json entry for <key> — add the server to .kiro/settings/mcp.json or pass --mcp-command", exit 2.
3. Hooks, written to `<root>/.kiro/hooks/`, same JSON shape as the existing files in that folder: `specimen-jar-pre.json` (trigger PreToolUse, matcher `@<key>`, command `npx --no-install specimen hook pre --server <key>`), `specimen-jar-post.json` (PostToolUse, same matcher, `... hook post --server <key>`), `specimen-jar-firewall.json` (PreToolUse, matcher `write`, `npx --no-install specimen hook firewall`).
4. Stop gate, written only when a non-blank `--test-server` command is given (or typed at the prompt "command that starts a disposable test instance of the server — never production; leave blank for no stop gate"): `<root>/.kiro/hooks/specimen-jar-stop.json` with `{"version":"v1","hooks":[{"name":"specimen-jar-stop","trigger":"Stop","timeout":60,"action":{"type":"command","command":"npx --no-install specimen hook stop --server \"<cmd>\""}}]}` (escape the command correctly for JSON and for the shell: a double quote inside <cmd> is an error, exit 2). The `hook stop` subcommand does not exist yet — a later turn adds it; init only writes the file. No default for the command is ever taken from mcp.json. Blank → print "no stop gate installed" and write nothing for it.
5. `<root>/.specimen/replay.json` (the existing strict schema: `allow` and `watch`): `watch` = every `--watch` glob, else (interactive) ask "paths that hold the server source (comma separated)", else `["src/**"]`. `allow`: when a test-server command is given, start it with the stdio client factory, call `tools/list`, and pre-fill `allow` with the tools whose `annotations.readOnlyHint === true`; every other tool: with a TTY ask `replay <tool> against your test instance? [y/N]`; with no TTY it is allowed only if named by an `--allow` flag; `--allow <tool>` for a name the server does not list is an error, exit 2. `--yes` allows every listed tool (print "allowed by --yes: <names>"). Without a test-server command, `allow` = the `--allow` flags (maybe empty) and print "allow list is empty — no jar can be replayed until you add tools to .specimen/replay.json". A failure to start the test server or list its tools: print one line, write replay.json with the `--allow` flags only, exit 0. The server child must always be closed.
6. `.gitignore`: unless `--commit-jars`, make sure the lines `jars/` and `replays/` and `.specimen/pending.jsonl` and `.specimen/hook.log` are present (append only the missing ones, create the file if needed, never reorder or remove lines). With `--commit-jars` do not add `jars/` and say "jars/ is committed: redaction rules apply — read .specimen/redact.json first".
7. Engine check: run `kiro-cli --version` through an injectable runner; if it cannot be started print "kiro-cli not found on PATH — hooks are written but the headless commands need it"; otherwise print its version line and the line "headless commands pin --agent-engine v3". Never fail on this.
8. Idempotent: a second run with the same arguments changes nothing and prints `kept` lines. Existing hook files and replay.json are kept unless `--force`; `.gitignore` and mcp.json are merged as above either way.
9. Last line: `next: restart the Kiro session, run your agent against <key>, then: specimen replay --server "<your test instance command>"`.
