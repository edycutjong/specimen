Facts about the Kiro hook (measured, do not re-discover): the Stop payload on STDIN has only `session_id`, `hook_event_name` and `cwd`. Printing `{"decision":"block","reason":"..."}` on STDOUT with exit 0 starts exactly one more agent turn and the agent sees the reason; exit 0 with no output lets the agent stop; a hook that is killed by its timeout lets the agent stop (the gate fails open). The PromptSubmit hook's STDOUT is added to the agent's context, so `hook prompt` must print nothing.

2. The pure decision function `decideStop(input)` in packages/core/src/stop-gate.ts, no node: imports. Input: `{ changedThisTurn: boolean, verdict: VerdictResult, redIds: string[], unfiledIds: string[], blocksSoFar: number, maxBlocks: number }`. Output: `{ action: "allow" } | { action: "block", reason: string } | { action: "allow", unresolved: string }`. Rules, in this order: not changedThisTurn → allow; unfiledIds empty (this covers SHIP, an empty jar set, all-skipped, quarantined orphans and spoiled lines: HOLD for those reasons never blocks, because nothing red is unfiled) → allow; blocksSoFar >= maxBlocks → allow with `unresolved` text naming the unfiled ids; otherwise block with a reason that starts `jars rattled or cracked:` lists every unfiled red jar id (sorted) and says in one sentence each what to do: keep the old contract so the jar replays calm, or run `specimen file <id>` to file a bugfix spec. The reason is at most 600 characters.
