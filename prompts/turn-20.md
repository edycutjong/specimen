Start a new Feature spec, Requirements-First, named replay-engine. Write only .kiro/specs/replay-engine/requirements.md (EARS acceptance criteria, numbered requirements). Do not write design.md or tasks.md yet and do not change any other file.

The feature: replay every recorded jar (from the jar-capture spec; read packages/core) against a NEW version of the MCP server, compare each replayed response with the jarred one, and decide SHIP or HOLD with one deterministic function that the CLI, a later Agent Stop gate and the browser cabinet all call. All logic is pure TypeScript in packages/core with no node: imports (it must also run in a browser bundle); process concerns stay in packages/cli.

What it must cover:
1. replay.ts: load every jars/*.jsonl line (a malformed line is "spoiled": counted and reported, never silently skipped); group by session_id and replay sessions in order of their first seq, calls in seq order, against a FRESH server per session (state such as booking ids must restart for every session). The engine is transport-agnostic: it takes a factory that returns a connected MCP SDK Client (stdio in the CLI via StdioClientTransport for the command given in --server; InMemoryTransport + an in-process server in the browser). It reads tools/list once per server and keeps both bodies (jarred response_text and replayed text) in the result.
2. Jar states: preserved (no change after normalisation, or additive-only changes, which are listed as compatible "+N field" unless --strict), rattled (any removed/value/type/length change), cracked (the tool is not in tools/list or the call fails at protocol level), unsealed (an unpaired post or an orphan pre entry, listed with its reason in .specimen/quarantine.json, never compared), skipped (the tool is not allowed in .specimen/replay.json {"allow": [...], "watch": [...]} — never replayed, never counted calm).
3. normalize.ts: remove the paths listed in .specimen/volatile.json {"volatile": ["/created_at", "/bookings/*/created_at"]} (JSON-pointer globs, * matches one segment) from both bodies before diffing.
4. diff.ts: a structural diff producing Change {path, kind: removed|added|value|type|length, was?, now?, note?}. Arrays of objects that all carry a unique id-like key (id, or a key ending in _id) are diffed by that key, so a dropped element is reported by its key (e.g. /rooms/r-08 removed) together with one length change on the array. A minimal rename/unit detector: when a removed numeric path and an added numeric sibling path share a name stem (total -> total_cents) and now = was × 10^n for n in 1..3, add the note "suspected rename from /total ×100" (the factor written out). Must-have negative fixtures as unit tests: 100 vs "100" is a TYPE change and never a rename; an unrelated removed/added pair whose values happen to differ by ×10^n (different stems) is NOT a rename. Money literals: the jarred text "total":425.00 parses to 425 and is compared as a number. Non-JSON responses are diffed as text lines.
5. verdict.ts (deterministic): SHIP iff at least one jar was compared AND no jar is rattled, cracked, unsealed or skipped AND no line was spoiled; otherwise HOLD with a reason ("no jars", "2 rattled", "3 not replayed: not in replay.json — allow book, cancel_booking in .specimen/replay.json to replay them against your disposable test instance", "1 quarantined: orphan pre-event — re-record the session", "1 spoiled line"). It also returns red (rattled + cracked), filed (red jars whose accession id is listed in a bugfix spec that passes check-spec), covered (HOLD AND ≥1 compared AND red > 0 AND filed = red AND nothing unsealed or skipped) and coverage {compared, tools_compared, tools_listed, tools_unrecorded} rendered as "N jars compared · T of K tools · not recorded: …". SHIP means "replay clean on the recorded set", never "this server is safe".
6. Replay result JSON (replays/<server>-<iso>.json): {v:1, server, started_at, jars: [{id, state, changes, compatible, ignored, replayed_text, replayed, error?, ms}], counts {preserved, rattled, cracked, unsealed, skipped}, schema_diff {tools_removed, tools_added, input_schema_changed} (tools/list of an optional --baseline server vs the target), verdict, red, filed, covered, reason, coverage}. The same redaction pass as capture runs on replayed bodies before anything is written.
7. spec-check.ts + "specimen check-spec <bugfix.md> --jar <id>": a filed bugfix spec counts only if it has the three headings "Current Behavior (Defect)", "Expected Behavior (Correct)", "Unchanged Behavior (Regression Prevention)"; ≥1 "WHEN … THEN the system" line, ≥1 SHALL, ≥1 SHALL CONTINUE TO; the jar's accession id; a fenced ```json specimen-repro block (one entry per covered jar: id, input, response_text, replayed response, changed paths) whose JSON equals the jar after canonical normalisation (key order and whitespace never fail it; an edited value fails "repro not verbatim"); every changed path of the jar; ≥1 preserved jar id cited under Unchanged; and the Expected Behavior names the jarred reference taken from the block by code (the v1 path and value, e.g. /total 425.00; the removed ids of a length change; the missing tool of a cracked jar) else FAIL "expected does not name the reference".
8. CLI "specimen replay --server "<cmd>" [--jars dir] [--baseline "<cmd>"] [--strict] [--json] [--out file]": exit 0 SHIP, 1 HOLD, 3 HOLD with covered = true, 2 usage error; text report whose first line is the verdict with its coverage, then one line per jar (id · tool · state · changed paths · note). Replay safety contract: the server command comes only from --server (never inferred from mcp.json or the jars).
9. Tests in vitest with fast-check properties where they fit (diff of a value against itself is empty; normalisation is idempotent; verdict is SHIP only under its rule), plus fixture evals: E3b (three rattled quote jars + one fixture spec listing all three ids → HOLD, covered; a spec missing one id → covered false naming it), E3c (no jars → HOLD "no jars"), E3d (all skipped / one skipped → HOLD "N not replayed"), E3e (one orphan → HOLD quarantined; one spoiled line → HOLD spoiled; every verdict line carries the coverage string), E4 (check-spec: missing or edited repro block fails, reordered keys pass, Expected not naming the reference fails), E6 (a diff only on /created_at with the default volatile policy → PRESERVED). The demo server in servers/hollow-inn (createServer("v1"|"v2")) is available for end-to-end tests: replaying v1 jars against v1 must be all preserved; against v2 the quote jar rattles with the ×100 rename note, an unlimited search_rooms loses r-08 and r-09, and cancel_booking is cracked.
