Add one command to the specimen CLI: `specimen file <jar-id> [--dry-run] [--replay <path>] [--timeout <seconds>]`. Work only in packages/cli (new file packages/cli/src/file.ts, register it in packages/cli/src/main.ts next to check-spec, tests in packages/cli/test/file.test.ts). Reuse packages/core (replayResultSchema, selectLatestReplay, checkSpec, canonicalJson) and copy the latest-replay lookup style of packages/cli/src/check-spec.ts. Do not touch jars/, servers/, packages/core or .kiro/. Do not commit. Keep the session short: read check-spec.ts, spec-check.ts (repro block part) and main.ts, write the code and tests, run the tests, stop.

Behaviour:
1. Load the Replay_Result (`--replay`, else the newest file in <root>/replays). Find the entry whose id is <jar-id>. Missing file, unknown id, or a jar that is not rattled or cracked: print one line to stderr and exit 2.
2. The signature group = every entry of the same tool and same state whose set of changed paths (entry.changes[].path, sorted) equals the target's, in Replay_Result order. For a cracked jar the set is empty, so the group is every cracked jar of that tool.
3. Slug = kebab-case of the tool name followed by the changed paths (non-alphanumerics become "-", runs collapsed, trimmed, max 48 chars); a cracked group uses `<tool>-missing-tool`. Example: quote with /total and /total_cents gives `quote-total-total-cents`.
4. Write `.kiro/specs/<slug>/bugfix.md` as a skeleton, exactly in this order: `# Bugfix Requirements Document`, blank, `## Introduction`, blank, a line `<!-- specimen:repro:start -->`, a fenced block opened with ```` ```json specimen-repro ```` holding a JSON array (2-space indent) with one object per jar in the group: `{"id", "input", "response_text", "replayed", "changed_paths"}` copied by code from the entry (input, response_text, replayed verbatim; changed_paths = entry.changes[].path in entry order), the closing fence, then a markdown table `| jar | path | kind | note |` with one row per change of every jar in the group, then `<!-- specimen:repro:end -->`, blank, `## Bug Analysis`, `### Current Behavior (Defect)`, `### Expected Behavior (Correct)`, `### Unchanged Behavior (Regression Prevention)` (each heading followed by a blank line). If the file exists already, overwrite it.
5. Build the curator prompt (a pure function, exported, unit-tested): the file path; "the repro block between the markers was written by the specimen CLI — keep it byte for byte, write the Introduction sentences above it and numbered lines under the three headings below it, follow specimen-bugfix.md"; the server (Replay_Result.server), tool, state and the group's ids; every change (path, kind, note); for each jar the reference the Expected section must restore (rattled field: the JSON pointer and its recorded value from response_text; removed array items: their ids; cracked: the missing tool name); the preserved jars of the same tool by id with their input (or the exact sentence "no preserved jar of <tool> was recorded" when there are none).
6. `--dry-run`: print the skeleton and the curator prompt to stdout, write nothing, run nothing, exit 0.
7. Otherwise run `kiro-cli chat --no-interactive --agent-engine v3 --trust-workspace --agent specimen-curator "<prompt>"` in the workspace root through an injectable runner (tests pass a fake runner — never call real kiro-cli in tests; never add --trust-tools or --trust-all-tools). Timeout = `--timeout` seconds, default 300: on timeout kill it, print "curator timed out after N s — no spec written", exit 21. Kiro exit code not 0: print "kiro-cli failed with exit code <n>" plus its stderr, exit 22.
8. After the curator: verify the text between the two markers is byte-identical to the skeleton's, then run checkSpec for every jar id in the group. Any failure: run the curator ONCE more with the failing checks quoted in the prompt, then re-check. Still failing: rename the file to `bugfix.rejected.md` in the same folder, print every `FAIL <id> <code>: <message>`, exit 20. All pass: print `filed <path> · PASS <id>, <id>…`, exit 0.
